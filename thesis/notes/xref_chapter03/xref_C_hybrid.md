## 2. Facts in code/NUTS the thesis omits but a reader would need

1. **Release gate semantics vs NUTS.** NUTS:198–200 describes a ±5° window plus a grasp-dwell condition; the implemented and recorded gate is a one-sided "directional turn ≥ 55°" with no grasp or dwell condition (`forge_transitions.py:755–760`). The thesis is correct; it may be worth one sentence that no grasp condition is required at release.
2. **Only the return is physically gated**; the four release waypoints advance on a fixed timer (`forge_transitions.py:969–975`). The thesis implies this but does not say it.
3. **Collection ran with task domain randomization disabled** (nominal gains, EMA 0.0625, no dead zone, zero observation noise, no mass/friction randomization) and without PhysX enhanced determinism (`collect_full_task_dataset.py:57–74`, `collect_dual_supervision_dataset.py:189–192`, GAP:1197–1199). Relevant to #30 and #45.
4. **Impulse details**: isotropic random direction in the world frame, applied as a constant force for exactly one policy step (66.7 ms), on one of `fr3_link1..7`, seed 0 (`random_arm_impulse.py:3–5, 34, 226–246, 279`).
5. **Calibration quality**: 27.46 mm translation / 3.50° rotation fit RMSE, status "measured", not deployment-validated (`camera_info.yaml:82–83`, HO:171–173, GAP:1183). A reader of §3.4.4 should know the magnitude of the calibration error the student must absorb.
6. **Point-cloud box numbers**: camera-frame AABB x∈[−0.39, 0.12], y∈[−0.25, 0.20], z∈[0.61, 1.17] m, depth 0.10–2.0 m, 128-point safety floor (`rgb_pointcloud_dp3_encoder.yaml:46–56`, HO:154–158).
7. **Visual-DR schedule**: dome light resampled with probability 0.3 per reset (intensity U(1000, 4000)), background with probability 0.5 per environment replacing only invalid-depth and ≥1.5 m pixels, table/nut/bolt per resetting environment, floor global (ref doc:202–206).
8. **Dataset excludes `reset_settle` rows**; episodes begin at the first policy row, so `sample_time_s[0]=0` is the first policy tick (GAP:856–858).
9. **"Handover" is a same-hand regrasp**: the pickup expert engages the nut at a handoff pose above the bolt, then the scripted transition opens the pinch, moves to the threading start pose, closes, and settles (YAML:6–22). Nothing bimanual.
10. **Hardware release proxy** (see #21): no nut-angle sensor exists on the cell; release is decided from grasp-frame yaw, and the deployment README explicitly "does not claim threading success from that proxy alone" (`DEP/apps/policy_rollout/README.md:338–341`). This matters for how Chapter 5 counts cycles.
11. **Teacher observation noise during training** (0.25 mm / 0.1°, 1 mm bolt frame) is in `tab:dr`; the collection zeroed it (#3 above).

## 3. Simulation-only vs real-pipeline implications

- **Implied real, actually sim-only**: the sentence at line 147 ("derived from the same physical events" at deployment) — the release event on hardware is a grasp-yaw proxy, not the nut rotation (#21). Everything else the sim-to-real subsection attributes to the real pipeline (eye-to-hand calibration, crop/intrinsics, aligned depth, point-cloud box, 4096 sampling, unified action path, impedance law) is present in the deployment code (GAP:1191–1204 "Already identical, no work needed"; controller law per `franka_forge_cartesian_impedance/README.md`), with the controller caveat of #44.
- **Implied both domains, actually real-only**: the "center-crop 640×480 → 640×360 → ÷2" step (#35, #47) is performed only on the physical stream; the simulator renders the cropped intrinsics directly.
